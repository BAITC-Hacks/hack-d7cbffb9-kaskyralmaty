## 2. Требования кейса (must-have)

1. Распознавание речи участников.
2. Понимание русского.
3. Понимание казахского.
4. Понимание шала-казахского (смешанной речи).
5. Автоматическое выделение поручений: ответственный, срок, суть.
6. Диаризация с привязкой поручения к конкретному человеку.
7. Экспорт итогового протокола в файл (PDF или DOCX).

Выход: транскрипт, структурированный список поручений и краткое саммари, экспортированные в файл.

**Жёсткое ограничение:** передавать аудио и текст во внешние облачные API запрещено. Модели только локальные или self-hosted. Поэтому **OpenAI API в самом решении не используем**. Допустимо только как инструмент разработки, например для генерации синтетических текстов тестовых совещаний, и это нужно раскрыть в README.

Опционально (только если останется время): дашборд статусов поручений, рассылка, классификация по срочности, интеграция с СЭД, подключение к Teams/Zoom/Meet.

Критерии жюри кейса: соответствие и работоспособность (25), техническая реализация, включая AI/agentic AI (25), README и воспроизводимость (25), ценность (15), потенциал и оригинальность (10).

### Особенности данных, которые надо учесть
- **Обе выданные записи полностью на русском.** Для казахского и шала-казахского нужны свои записи: 1–2 коротких фрагмента, записываем сами.
- Совещание 1: поручения продиктованы явно («Первое: … ответственный …, срок до 15 октября»).
- Совещание 2: поручения неявные («пусть Ерлан до конца недели подготовит претензию», «за две недели найдите…»). Нужна нормализация относительных сроков. В эталоне бывает «Не указан», «1 неделя», «Среда».
- Диаризация выдаёт только SPEAKER_N. Имена надо выводить из контекста разговора, например по фразе «Гульмира Сериковна, вам слово».

## 3. Железо: NVIDIA Brev = «сервер заказчика»

Кредиты Brev выданы организаторами, чтобы эмулировать железо клиента (закрытый контур). Self-hosted модели на Brev — это ровно тот on-prem сценарий, которого требует кейс.

- Инстанс: `practical-aquamarine-lamprey`. AWS g7e.2xlarge, **RTX PRO 6000 Blackwell Server, 96 ГБ VRAM**, compute capability 12.0, драйвер 595, CUDA 13.2, 8 CPU, 62 ГБ RAM, Ubuntu 22.04, Docker с nvidia runtime, 195 ГБ свободного диска.
- Доступ с Mac: `brev refresh`, затем `ssh practical-aquamarine-lamprey`. Логи проверки лежат в `docs/runs/`.
- Цена $4.08/час, в остановленном виде $0.04/час. Бюджет $50.
- **В 18:00 инстанс обязательно остановить (Stop)**, иначе за ночь уйдёт весь бюджет.
- Blackwell новый. Старые сборки PyTorch и CTranslate2 могут упасть с ошибкой «no kernel image». Нужно проверить faster-whisper на GPU в первую очередь. Запасной вариант: Whisper через `transformers`.

### Уже запущено на инстансе (13:51)
Контейнер `llm`: vLLM 0.30.0, модель качается в `~/hf-cache`.
```bash
docker run -d --name llm --gpus all --ipc=host -p 127.0.0.1:8000:8000 \
  -v ~/hf-cache:/root/.cache/huggingface --restart unless-stopped \
  vllm/vllm-openai:latest --model nvidia/Qwen3.8-27B-NVFP4 --served-model-name qwen3.8-27b \
  --max-model-len 32768 --kv-cache-dtype fp8 --gpu-memory-utilization 0.45 \
  --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_xml
```
Порт открыт только на localhost инстанса. Проверка: `ssh practical-aquamarine-lamprey 'docker logs --tail 20 llm'`. Когда модель готова, `curl localhost:8000/v1/models` на инстансе отвечает. Режим размышлений выключается в запросе: `chat_template_kwargs: {"enable_thinking": false}`. Если NVFP4 или Qwen3.8 не заведутся, запасная модель — `Qwen/Qwen3.6-27B`.

## 4. Утверждённый стек

| Слой | Решение | Почему |
|---|---|---|
| Язык и окружение | Python 3.11, **uv** (`pyproject.toml` + `uv.lock`) | закреплённые версии, воспроизводимость |
| Сервис | FastAPI + одна HTML-страница (загрузка аудио → протокол) | минимум обвязки |
| ASR | **faster-whisper large-v3**: таймстемпы и язык по сегментам | RU хорошо, KZ посредственно |
| ASR для казахского (stage 3) | сегменты с языком `kk` повторно распознаются через **SeamlessM4T-v2-large** | вывод из статьи Алихана, пункт «инновация» |
| Диаризация | **SpeechBrain ECAPA** эмбеддинги + кластеризация | pyannote и WhisperX закрыты (нужен HF-токен, то есть личный аккаунт, а правила проверки это запрещают) |
| LLM | **Qwen3.8-27B NVFP4 в vLLM** (OpenAI-совместимый API) | Apache 2.0, FP4 аппаратно на Blackwell |
| Агент | **PydanticAI**: модели Pydantic для `Assignment` и `Protocol`, инструменты агента | структурированный вывод и валидация, Python-стек |
| Экспорт | python-docx (DOCX) | must-have 7 |
| Оценка | jiwer (WER) + свой скрипт P/R по поручениям против эталонных протоколов | цифры для README и демо |
| Развёртывание | `docker compose` на GPU-машине (ASR-сервис + vLLM) | сценарий «сервер заказчика» |

Отклонено и почему:
- **Qwen3-ASR**: нет казахского среди 30 языков.
- **WhisperX целиком**: pyannote требует токен, выравнивания для казахского нет.
- **pi (pi-mono)**: TypeScript/Node, экспертам пришлось бы ставить второй рантайм.
- **OpenAI в рантайме**: запрещено условием кейса.

Инструменты агента (черновой набор):
- `get_segment`: посмотреть фрагмент транскрипта;
- `resolve_speaker`: сопоставить SPEAKER_N с именем по контексту;
- `normalize_deadline`: относительный срок → дата от даты совещания;
- `add_assignment` / `validate`: у каждого поручения есть суть, ответственный (или «не указан»), срок (или «не указан») и ссылка на реплику-источник.
